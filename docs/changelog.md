# Changelog

## 1.1
- Staged populate (`features`, off by default): RTG-Plus 9.0.3's biome decorations run on a terrain worker against a journal, and the server thread applies them at tick end in order, then runs the rest of that chunk's populate. A populate whose window overlaps a pending job waits; a pending chunk is not sent, not unloaded and is saved as not populated; a job that aborts or waits too long runs inline. It runs only with the RTG classes it was written against (SHA-256 check). `ChunkStewardAPI` is version 4: `registerPopulateScope`. See `docs/staged-populate.md`.
- `pipeline.speculative` (default true) queues idle-preload and stage 2 terrain behind player chunks. Those callers install a finished worker result and leave an unfinished one for a later tick. The stage 2 populate phase stays on the server thread. `ChunkStewardAPI` is version 3: pipeline active, queue size, install time, `isChunkReady`, `isPipelineContext`, and `JobPreparer`. Existing methods keep their meaning. See `docs/api.md` and `docs/pipeline.md`.
- Terrain pipeline can generate a dimension's own chunk generator off the server thread when that exact class is in `pipeline.allowedGenerators`. The list still defaults to empty. A clean `/chunksteward pipeline verify 10000` adds the class and keeps it across launches. A listed class runs in every dimension that uses it. That includes RTG, NetherEx, Nether API's end, the Aurorian, Atum, Twilight Forest, the Aether, the Beneath, the Betweenlands, and Emptiness, plus vanilla hell and end, once each is listed. On a worker or verify thread, RTG uses that generator's `Random`, locks each terrain `generateNoise` and surface `paintTerrain`, and keeps a private cellular cache. The server thread still uses the shared `RTGWorld`. See `docs/pipeline.md`.
- Pipeline worker-thread fixes for state the generator copies still shared: per-thread `IntCache`; the worker biome provider only for its own dimension (also through `WorldProvider`); Nether API sea level per thread; Barrend uses the generator random; Aurorian reseeds by position; Betweenlands noise buffers per thread (array reads only); `World.setRandomSeed` per thread on pipeline threads; end city starts recorded in Nether API's end `recreateStructures`; Twilight highlands surface blocks per thread; Atum keeps the 16×16 biomes, lays out pyramids on workers, and verify drops the pyramid plates it created. Stage 2 and idle preload skip a dimension verify has paused. The late mixin loader skips a mod source it cannot read instead of queueing nothing. Generator mods are compile-only (`libs/mods`); every mod-specific mixin is in a class-gated late config, and the build checks that nothing else names those mods. See `docs/pipeline.md`.
- Below `throttle.tpsFull` (19), the headroom allowance gains `headroomBoostMs` (60) scaled by an admission factor: 1 at 19 TPS, 0 at `tpsClamp` (10). At 19 and above every chunk is still admitted, and vanilla's loop still stops 50 ms after a success. The shortcut that also admitted everything when the 20-tick average was under 50 ms is gone. `getLoadFactor` and `getHeadroomMs` are unchanged. See `docs/throttle.md`.
- Random-tick guard: `provideChunk` returns on a single flag check when no random tick is in progress, so lighting no longer calls `RandomTickGuard.intercept` on every light read. During `WorldServer.updateBlocks` an unloaded chunk still gets an empty chunk. See `docs/random-ticks.md`.

## 1.0
- First release. Version 1.0 (`build.gradle`, `ChunkSteward.VERSION`); behaviour as tested in 0.3 apart from the defaults below. `ChunkStewardAPI` is unchanged (still version 2).
- `throttle.tpsFull` default 19.0 (was 19.5): chunks are admitted freely while measured TPS stays at 19 or above (a 100-tick mean up to about 52.6 ms), so generation keeps up while the server is only slightly behind. Load factor 1 and `isServerBehind()` false from 19.0; `throttle.tpsLoaded` stays 15, so API consumers see the load factor reach 0 at the same point as before. An existing cfg keeps its old value; set `tpsFull=19.0` by hand to pick this up.
- Stage 2 is faster: `stage2.maxTickMs` default 30 (was 20) and `stage2.maxPerMinute` 240 (was 120). With 20 the limit sat at the server's baseline tick (20 to 22 ms) and stage 2 managed about 1.2 chunks a second; 30 / 240 were set in the DEVBOX and server cfgs from 2026-10-20 before becoming the defaults. Existing cfgs keep their values.

## 0.3
- Renamed from Lazy Chunks 1.12 to **Chunk Steward**: modid `lazychunks` → `chunksteward`, package `com.apocollis.chunksteward`, config `config/chunksteward.cfg` (same keys; copy `lazychunks.cfg` over), jar `ChunkSteward-<version>.jar`, mixin config `mixins.chunksteward.early.json`. New logo (credits in `NOTICE.md` and `mcmod.info`). The deploy script now also deletes `LazyChunks-*.jar`, since the old and new jars must never both load. Existing worlds log a one-time "saved with mod lazychunks which appears to be missing" notice, which is harmless.
- Populate budgeting: a populate that would push the current tick past `populate.tickBudgetMs` (30) is queued and run later, nearest and most-forward first; chunks near players, and players in login warmup, populate at once. Fixes the multi-second stalls of 0.2 test logs, which were populate bursts of chunks loaded from disk (including terrain-only preload chunks), not terrain generation. See `docs/populate.md`.
- Cascades in terrain-only mode, nothing cancelled: a chunk generated while another is populating is populated later through the queue, so ore, trees and village pieces still see real terrain and place normally. Cascade chunks no player owns are held and then released (vanilla never unloads them). Cascades are counted by the causing `IWorldGenerator` class in the status log.
- Random-tick guard: during `WorldServer.updateBlocks` an unloaded chunk read returns an empty chunk instead of generating (lava and fire spread, grass spread). `randomTicks.guardEnabled`. See `docs/random-ticks.md`.
- Preload rewritten: always-on, two tiers measured from the live view distance and excluding the area vanilla loads. Idle (still 1 s): full out to view + 2, terrain only out to view + 12. Moving (slow only): terrain-only forward cone out to view + 3. Holds off while chunks are waiting, recent generation is busy (`busyChunks`), populates are backed up, or ticks are over the tier limit; per-player per-minute limit; known-generated cache avoids repeated region-file checks.
- Config: new `populate`, `randomTicks` sections and new `preload` keys. Removed `preload.radius`, `terrainOnlyRadius`, `terrainOnlyMaxChunks`, `stationaryTicks` (the old keys in an existing cfg are dropped on the next write); `preload.maxTickMs` is now the idle tier's limit.
- Ticket exemption: a chunk held by a Forge chunk ticket owned by a mod in `populate.ticketExemptMods` (default `roguelike`) populates at once and is taken out of the queue, so Roguelike's dungeon build job is never racing a later queue populate. Counted as `ticket-exempt` in the status log. Cascades are never exempt.
- Held chunks (preload and cascades) share `ChunkHolds` and are never released while a player watches them or a Forge ticket owns them.
- Status log: populate queue, cascades by generator, held chunks, preload tiers and yields, random-tick guard counts and sources.
- Stage 2, home-area pregen (`stage2.enabled`, default on). Hotspots are a player's bed or respawn point, or any place where players have stayed about `dwellMinutes` (10) in total. Dwell is sampled every 10 s against a fixed anchor (32 blocks): within it the sample is credited to the player's 8x8-chunk cell, beyond it the anchor moves; a 3x3 block of cells reaching the threshold creates a hotspot at its dwell-weighted centroid. Counters are saved with the world and resume after a player leaves and returns. See `docs/stage2.md`.
- While a player is near a hotspot, after their preload queue has finished and while the server has room (the same hold-offs as preload), the area is generated terrain-only out to `radiusTerrain` (30), then populated out to `radiusFull` (20), one operation every 4 ticks. Progress is saved per hotspot and resumes after a restart.
- No cap on hotspots: `warnTotalChunks` (100,000) warns, `maxTotalChunks` (0 = none) can limit total chunks generated. Hotspots within `mergeRadiusChunks` (8) merge.
- Saved data: `chunksteward_hotspots` per dimension (`WorldSavedData`).
- Operator commands `/chunksteward` (status, chunkinfo, queue, holds, log, pregen, hotspots list/here/add/remove/reset). See `docs/commands.md`.
- Stage 2 populates pass the populate budget deferral through `StageGate.beginStage2()`; stage 2's own generation is not counted as busy generation.
- Status log: `stage2 hotspots N, generated, populated, yielded (last reason), total`.
- Fix: the dedicated server crashed at world creation with `NoClassDefFoundError: net/minecraft/world/chunk/EmptyChunk`. The random-tick guard returned vanilla `EmptyChunk`, which is client-only; it now returns `StewardEmptyChunk`, a plain `Chunk` subclass that exists on both sides. The integrated server hid this because it has the client classes. Found by the first dedicated-server test (2026-10-19).
- RTG-Plus support: RTG-Plus 9.x chunks (`rtg.world.gen.LatePopulatingChunk`) populate through an outer method the stage gate did not see, so the populate budget, queue, cascade deferral, terrain-only preload, stage 2 and the populate metrics were bypassed for the RTG overworld. A late mixin (`mixins.chunksteward.rtg.json`, queued by `ChunkStewardLateMixinLoader` only when the RTG jar contains the class) now gates RTG's populate window per chunk. Older RTG and other dimensions are unchanged. See `docs/populate.md`.
- Movement sampling (`movement.sampleTicks`, default 10, 1 to 40): player speed, direction and standing-still are measured from the position change over the sample window instead of every tick. Cheaper to run; the emergency radius, chunk order and idle preload react up to one window (0.5 s) late. `1` is every tick.
- `throttle.tpsFull` now defaults to 19.5 (was 20): a 100-tick mean just over 50 ms still reads full. Load factor 1 from 19.5 TPS; `isServerBehind()` false from 19.5; full-TPS admission from 19.5.
- MIT licence added (`LICENSE`); the logo is excluded (see `NOTICE.md`).
- Measured TPS and load factor: `min(20, 1000 / mean tick work of the last 100 ticks)`, scaled linearly between `throttle.tpsLoaded` (15) and `throttle.tpsFull` (19.5, a small dead band under 20 so a 19.88 TPS blip still reads full). Reported in the status log and `/chunksteward status`; API version 2 adds `getMeasuredTps()` and `getLoadFactor()`, and `getHeadroomMs()` and `isServerBehind()` follow them. Chunk admission stays the per-tick headroom under `throttle.targetTickMs` (40): a TPS-driven credit throttle and then a feedback budget were tried in 0.3 development and removed after DEVBOX tests showed chunks held and arriving in bursts at 20 TPS. See `docs/throttle.md`.
- `throttle.admitAtFullTps` (new, default on): while the server holds 20 TPS (measured TPS at `tpsFull`, or the 20-tick average tick work under 50 ms), every chunk is admitted, however long the current tick is; the `targetTickMs` headroom rule applies below 20 TPS. The headroom rule alone held chunks to 5 a second at 20 TPS in this pack, because one chunk costs more than the headroom. `false` restores the old behaviour.
- `preload.busyIgnoreMods` (new, default `roguelike`): chunks generated while held by a Forge ticket of one of these mods do not count as player demand, so preload, stage 2 and `ChunkStewardAPI.isGeneratingChunks()` ignore them (API meaning unchanged: "chunks generated for players"). A Roguelike dungeon's footprint loading made `isGeneratingChunks()` true for the whole PREPARE pass and the build paused itself (1.1 s of work over 165 s in the 2026-10-17 12:39 DEVBOX run). Status log: `mod-ticket generation N`.
- Fix: stale state after re-entering a world. The integrated server restarts its tick counter at 0 every time a world is entered, and tick numbers kept from the previous world made the save pause last about 95 s and stopped the starvation guard. `SessionState.reset` now clears all per-session state at server start and stop, and when the tick counter goes backwards or a different thread ticks (`session state reset (reason)` in the log); tick comparisons treat a stale tick as long ago.
- Temporary diagnostics (`logging.debug`, default off; every line starts with `dbg`): per second, why chunk provision calls were passed, bypassed, admitted or deferred and what the populate gate decided; per player, a scan of the chunks within 4 chunks (missing, loaded but unpopulated and why); near chunks that get deferred are logged as they happen. Two always-on sanity warnings (random-tick guard active while player chunks are provided, empty chunk in a chunk map entry). See `docs/diagnostics.md`.
- Populate and structure attribution in the status log: the populate stage is split into generator populate, structures (by `MapGenStructure` class), world generators and other; the terrain stage lists `MapGenBase` map-gens by class (caves, ravines, structure layout). Plain HEAD/RETURN injects on vanilla classes. See `docs/metrics.md`.
- Pacing API for other mods: `com.apocollis.chunksteward.api.ChunkStewardAPI` (average tick ms, headroom, remaining budget in the current tick, server-behind, generating-chunks, populate queue size). Read-only, additive. See `docs/api.md`.

## 0.2
- Direction-weighted order for missing chunks: distance penalised by angle from the player's view direction (still) or travel direction (fast); cached scores, stable sort; `directionPenalty = 0` is vanilla order. Re-sort when a player turns past `resortAngleDegrees`.
- Speed-scaled emergency radius above `emergencyMinSpeed`, capped at `emergencyMaxRadius`.
- Terrain-only ring for idle preload, from `radius` out to `terrainOnlyRadius` (default 20, cap `terrainOnlyMaxChunks` per spell), with populate suppressed through the new stage gate.
- `StageGate`: one gate for populate suppression and light deferral.
- Light deferral of the per-tick `checkLight` retry on terrain-populated, unlit chunks during heavy generation (default off), drained within a per-tick budget. Gated at `Chunk.checkLight()` HEAD, not in `onTick`, because Somnia's coremod (and Tweaks' overwrite of it) own that call.
- Status log: waiting chunks, wait time, stage timing (terrain, populate, light), top world generators by class, gate counters.
- Fix: preload peeked chunks with `getLoadedChunk`, which cancels a pending unload; it now reads `loadedChunks`. Released chunks are re-checked and re-queued if something pulled them back.
